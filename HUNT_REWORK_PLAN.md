# План: фотоохота поглощает фотомиссию и фразы

Спецификация для реализации. Составлена после разбора текущего кода; решения по
развилкам приняты владельцем проекта и зафиксированы ниже.

## Что делаем

1. **Фотомиссия дня удаляется полностью** — её идея дублирует фотоохоту.
2. **Игра «Фразы» перестаёт быть отдельной** и становится третьим заданием фотоохоты.
3. **Фотоохота: 3 задания в день** — два из пула (как сейчас) и третье персональное,
   собранное из присланных игроками прилагательных и существительных.
4. **Фото можно переснимать** сколько угодно, пока игрок не нажмёт «Готово».
   После подтверждения снимки блокируются и уходят на голосование.
5. **Голосование переезжает на главную**: виджет показывает чужие фото по одному —
   заголовок с текстом задания, снимок, кнопки оценки 0–3 и отдельная реакция «смехуище».

## Принятые решения

| Развилка | Решение |
|---|---|
| Очки за оценки 0–3 | **Сумма всех оценок.** Фиксированные +8 за находку убираем — качество решает всё. |
| Третье задание | **Каждому своя пара** из чужих слов, как в нынешних «Фразах». |
| Старые данные фотомиссии | **Удалить полностью** — таблицы, файлы снимков и начисленные очки. |

⚠️ Третий пункт необратим и затрагивает реальные данные в `server/data/quest.db`.
**Перед миграцией сделать резервную копию:** `cp -r server/data server/data.bak`.

## Схема БД

Удалить (в `db.js`, миграцией `DROP TABLE IF EXISTS`): `photos`, `photo_votes`,
`phrase_rounds`, `phrase_words`, `phrase_assignments`.
Файлы снимков фотомиссии и фраз (`photo-*.jpg`, `phrase-*.jpg` в `data/uploads`)
удалить отдельным проходом. Колонка `days.mission_idx` больше не нужна — снимается
перестроением таблицы (в `db.js` уже есть образец такой миграции для `days`).

Добавить:

```sql
-- Слова игрока на день: основа для персональных третьих заданий.
CREATE TABLE IF NOT EXISTS hunt_words (
  date TEXT NOT NULL,
  user_id INTEGER NOT NULL REFERENCES users(id),
  adjective TEXT NOT NULL,
  noun TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (date, user_id)
);

-- Выданная игроку пара: фиксируется при первой выдаче и больше не меняется.
CREATE TABLE IF NOT EXISTS hunt_pairs (
  date TEXT NOT NULL,
  user_id INTEGER NOT NULL REFERENCES users(id),
  adjective TEXT NOT NULL,
  noun TEXT NOT NULL,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (date, user_id)
);

-- Подтверждение: до него фото можно менять, после — они видны для голосования.
CREATE TABLE IF NOT EXISTS hunt_submissions (
  date TEXT NOT NULL,
  user_id INTEGER NOT NULL REFERENCES users(id),
  confirmed_at TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (date, user_id)
);

-- Оценка одного снимка одним игроком. score 0..3, funny — «смехуище».
CREATE TABLE IF NOT EXISTS hunt_votes (
  date TEXT NOT NULL,
  item_idx INTEGER NOT NULL,
  voter_id INTEGER NOT NULL REFERENCES users(id),
  photo_user_id INTEGER NOT NULL REFERENCES users(id),
  score INTEGER NOT NULL CHECK (score BETWEEN 0 AND 3),
  funny INTEGER NOT NULL DEFAULT 0,
  created_at TEXT NOT NULL DEFAULT (datetime('now')),
  PRIMARY KEY (date, item_idx, voter_id, photo_user_id)
);
```

`hunt_photos` остаётся как есть — ключ `(date, user_id, item_idx)` уже подходит
для замены снимка через `UPDATE`.

## Задания дня

`daily.js`: `HUNT_ITEMS_PER_DAY` меняется с 3 на **2** — третье задание персональное
и в `days.hunt_items` не хранится. Выбор двух целей из хеша даты не трогаем.

**Выдача персональной пары — лениво, без раундов.** Когда игрок запрашивает охоту:
если он сдал свои слова и есть хотя бы один другой игрок со словами за этот день,
собираем ему пару из чужих слов (прилагательное от одного, существительное от другого,
свои исключаем) и пишем в `hunt_pairs`. Пока чужих слов нет — третье задание
показывается как «ждём слов от других». Такой подход снимает проблему разного
времени захода, которая была у раундов в `phrase.js`.

Функция `assignPairs` из `server/src/phrase.js` рассчитана на разовую раздачу всем
сразу и здесь не подходит — файл удаляется, выбор делается по одному игроку.

## API

Удалить: роутер `photos.js` и `phrase.js` целиком, их подключение в `index.js`
(строки 9, 13, 31, 35) и импорт `assignPairs`.

`routes/hunt.js` переписать:

| Метод | Назначение |
|---|---|
| `GET /api/hunt` | Состояние дня: три задания, свои снимки, флаг подтверждения, свои слова. |
| `POST /api/hunt/words` | Сдать/переписать пару слов на день. Только пока игрок не подтвердил. |
| `POST /api/hunt` | Загрузить **или заменить** снимок: `photo` + `item`. Старый файл удаляется. Блокируется после подтверждения. |
| `POST /api/hunt/confirm` | Зафиксировать все снимки дня. Требует снимок хотя бы на одно задание. Необратимо. |
| `GET /api/hunt/vote` | Очередь на голосование: чужие подтверждённые снимки, которые игрок ещё не оценил, по одному. Доступно только тем, кто подтвердил свои. |
| `POST /api/hunt/vote` | Оценка: `itemIdx`, `photoUserId`, `score` 0–3, `funny` boolean. |

Обработка изображений — как в существующих играх: sharp с `.rotate()`,
вписыванием в 1200×1200 и JPEG качества 78. Имя файла: `hunt-<date>-i<idx>-u<id>-<hex>.jpg`.

## Подсчёт очков

`scoring.js`: убрать блоки `photos`, `photo_votes`, `hunt_photos` (фиксированные
`itemPoints`), `phrase_words`, `phrase_assignments`. Добавить:

- **Сумма оценок:** каждому автору снимка начисляется сумма всех `hunt_votes.score`
  за его снимки.
- **Бонус «смехуище»:** по каждому дню считаем, у кого больше всего `funny`; все,
  набравшие максимум (при максимуме больше нуля), получают +5.

Очки бинго и цепочки не трогаем.

## Проверка

Тестировать на отдельной базе, не трогая рабочую:

```bash
DATA_DIR=/tmp/hunt-test PORT=3100 node server/src/index.js
```

Сценарий: два игрока сдают слова → у каждого своё третье задание из чужих слов →
оба грузят снимки → замена снимка работает до подтверждения и отклоняется после →
после подтверждения каждый видит снимки другого в очереди голосования →
оценки 0–3 суммируются в таблице лидеров → «смехуище» даёт +5 лидеру,
а при равенстве — всем, кто набрал максимум.
